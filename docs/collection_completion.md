## What is complete

- All 52 single-activity clips are regenerated at exactly 25 Hz, with finite
  values, integer Unix timestamps, traceable crop bounds and 5–10 s durations.
- Each activity retains at least 90 s using clips alone. Current counts and
  durations are in `data/quality/status.json`, generated by the pipeline.
- Gaps are identified independently for both sensors. The whole-recording
  filter rejects them; the recovery path splits at the union of the gap spans,
  filters each block independently, and trims one second at each boundary.
- Four recoverable unlabelled sequences are exported from the current sessions.
  They preserve original times and are never concatenated across missing data.
  Bounds and source hashes are in `data/quality/unlabelled_sequences.csv`.
- The raw signal report figure, six-axis plots, rate table, duration plot and
  session diagnostics are available in the executed notebook.
- Metadata covers all raw recordings, including the four pilots. Unknown pilot
  locations are explicitly `not_recorded`, rather than inferred.

## How to use the existing data honestly

Use the 44 files in `data/processed/train/clips/*.csv` for supervised emission initialisation and
training-only feature selection/scaling. The clip labels come from the original
single-activity recordings. Signal inspection was used to select crop intervals,
not to claim video verification or to invent a new activity label.

Single-activity clips provide observations of persistence but not reliable
cross-activity transition counts. Initialise cross-activity transitions with a
clearly stated prior (for example, persistent states with small nonzero exit
probabilities) and explain that assumption in the report. Choose this using
training data/validation only; do not tune on unseen test recordings.

Optionally use `data/processed/unlabelled/sessions/*.csv` for Baum–Welch training.
Each file is an independent sequence. It has **no activity column**. Session 1's
different grip is a real distribution difference that may affect Gaussian
emissions; compare supervised-only and EM-refined models rather than assuming
EM improves classification. Any such comparison/tuning must precede the final
unseen-data evaluation. Do not report labelled session training accuracy.

The original session label table is approximate diagnostic annotation, not
verified ground truth. Do not shift its boundaries to match a guessed movement
pattern, relabel gaps as still, rotate axes to resemble the clips, or manufacture
extra activity samples. Session 2 contributes only its surviving continuous
portion; the long outage and short tail contribute no training observations.

The original plan requested two labelled **training** sessions. That was a design
choice, not a rubric requirement. It has been replaced by labelled clips plus
optional independent unlabelled sequences. Phase 4 now reserves **eight whole clips** from the original collection as test data before any model fitting. These files are removed from training outputs and fixed in `data/split_manifest.csv`. Existing quality inspection is disclosed; recovered unlabelled blocks are never evaluation ground truth. See `phase4_test_data.md`.

## Reproduce the checks

From the repository root, using the pinned environment:

```bash
.venv/bin/python scripts/preprocessing.py --require-complete
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/jupyter notebook notebooks/hmm_activity_recognition.ipynb
```

Run the notebook top-to-bottom. The strict pipeline command verifies the revised
44-training/8-test partition and collection requirements and writes a fresh readiness report. It does not certify
video evidence, session labels, or generalisation outside the held-out collection. Derived output
directories are pipeline-owned: obsolete generated CSVs are removed on rerun.
All raw files and original labels are preserved.

`data/session_review.csv` records why the original sessions are unverified. A
future verified entry requires actual evidence and a matching raw-plus-label
fingerprint, not this approximate schedule. No such approval has been entered.

## Reporting the limitations

State that this is a single-participant activity-recognition demonstration using
a protocol-specific orientation cue. Jumping is an impact activity, not evidence
of real fall detection. Explain the session outages, independent sequence
recovery, unverified session timing, changed grip, transition prior, and any
effect of unsupervised refinement on genuinely unseen evaluation.
